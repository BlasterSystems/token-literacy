# Project Instructions

## Project

**token-literacy** — Local-first token ledger for Claude Code and Codex: per-turn fresh vs cached input, output, and API-equivalent cost, with a local dashboard.

- Languages/components: Go 1.24+ collector (`cmd/tokenledger`, `internal/...`); SQLite ledger; server-rendered HTML/SVG dashboard; optional Tauri v2 tray shell in `src-tauri/` (M5). Claude Code OTel and Codex rollout JSONL are the only v1 sources.
- Build: `make build`
- Test: `make test`
- Run: `make run`
- Task convention: Task identifiers use the `TL-<number>` convention; task files in `tasks/`, milestone plan in `docs/PLAN.md`.
- Public/OSS: Apache-2.0; repository `BlasterSystems/token-literacy`; no telemetry; no prompt or tool content in the ledger.

Treat values marked "Not configured" or "Not detected" as unknown. Inspect project-owned configuration or ask the user instead of inventing an answer.

## Architecture Decisions

Create an ADR when a decision is durable, cross-cutting, security-sensitive, expensive to reverse, or changes data, deployment, dependencies, or integration boundaries. Do not create ADRs for routine refactors or local implementation details.

Use `docs/adr/template.md`. Accepted ADRs are historical records: supersede them with a new ADR rather than rewriting the original decision.
